# Implementation Plan: Salon Onboarding

**Branch**: `2026-10-14-salon-onboarding` | **Date**: 2026-10-14 | **Spec**: [spec.md](spec.md)

## Summary

A company carries `is_onboarding_pending` and `onboarding_step`, set by `CreateCompany`. Dismissing
the welcome screen leads to `onboarding`, which redirects to the saved step. Four steps live at
their own URL behind one middleware that checks owner, pending and step. Step 1 calls `SetUpSalon`,
which renames the company and creates or updates the headquarters location; steps 2 to 4 are
placeholders calling `CompleteOnboardingStep`. Choices are argued in [research.md](research.md).

## Constitution Check

| Principle | Status |
| --- | --- |
| I. Actions hold the logic | Pass. `SetUpSalon` and `CompleteOnboardingStep` write and reuse `UpdateCompany`, `CreateLocation`, `UpdateLocation`. View models only read. |
| II. Simplicity | Pass. One enum, one middleware, two actions, one view model extended once. |
| III. Tested | Pass. Tests listed below. |
| IV. Laravel conventions | Pass. Migration edited in place (pre-production rule); its existing `down()` is left alone. |
| V. Localized | Pass. Copy through `__()`; country and time zone names come localized from `intl`. No destructive action. |
| VI. Accessible | Pass if the tracker is an `ol` with `aria-current="step"`, done state carried by text as well as the tick, selects labelled, time zone help tied with `aria-describedby`. |
| VII. One core | Justified gap: no API endpoint and no webhook. Onboarding is back office presentation; the location it creates already goes through the shared actions. |
| VIII. Short record | Pass. |

Post design re-check: unchanged, all pass.
